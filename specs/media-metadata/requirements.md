# 音视频元数据精确嵌入：需求草案

日期：2026-09-19；用户于 2026-09-20 授权实施。当前证据见 [implementation.md](implementation.md)。

研究证据见 [research.md](research.md)，具体技术决策见 [design.md](design.md)。用户已澄清：截图来自其他软件，仅作为字段展示参考；本项目不承担该软件的异常诊断或复现。

## 目标与用户故事

作为下载用户，我希望文件标题、作者、日期、来源等与内容一致，在 Windows 属性和播放器中尽可能正确显示；不希望为了填满属性而写入错误信息。

作为音频收藏用户，我希望作品艺术家、专辑、曲目与上传频道、播放列表分开，转出音频时保持可信信息。

作为批量下载用户，我希望每个任务按照创建时的设置执行；某个标签失败不损坏已完成的音视频。

## 范围

- 第一阶段：普通视频、纯音频、快速下载、精细下载、播放列表和频道中逐条媒体任务；MP4 / M4A 核心属性优先。
- 兼容回归：字幕、封面、SponsorBlock、区间截取、VR 转换、多音轨、重试、队列恢复。
- 单独字幕或封面任务不新加音视频元数据步骤。
- 扩展：MP3、FLAC、OGG/Opus、MKV/MKA；其他容器以已验证字段子集为准。
- 此次不改写用户现有媒体，不发布版本；以 FluentYTDL 自身正确实现为目标，不以复现或修复参考软件的问题作为前置条件。

## 验收标准

### R1：任务设置准确生效

- 当用户在任务中明确关闭嵌入时，系统应保持该选择，不受全局开关、音频预设、旧 postprocessor 列表再次开启的影响。
- 当任务排队后全局设置变化时，系统应使用任务快照；恢复和自动重试应继承同一政策与版本。
- 当用户关闭文本元数据时，系统应保持封面和字幕的独立选择；不主动清空源媒体原有标签。

### R2：语义与来源准确

- 当来源提供有效字段时，系统应按对应语义嵌入，并可追溯到来源字段。
- 当仅有频道、播放列表、分类、关键词时，系统不得将其默认冒充音乐艺术家、专辑、曲目号或流派。
- 当普通视频采用频道作为兼容作者显示时，系统应明确这是频道来源；不得写作推断的音乐作品艺术家。
- 当源字段缺失、无效或无可靠对应关系时，系统应留空或报告不支持，不写 `NA`、空对象、虚构值。
- 当源信息存在中文、emoji、换行、多艺术家或逗号名称时，系统应保留语义，不因拆分或编码破坏内容。

### R3：日期与年份可靠

- 当提供有效完整日期时，系统应分别保留完整日期语义和正确四位显示年份；不得把 `YYYYMMDD` 直接当作年份。
- 当仅有有效年份时，系统不得自行补出月日；非法日历日期必须拒绝。
- 当上传日与作品发行日不同，系统应按内容角色选择显示年份，并分别保留两种来源日期。
- 当验收日期规则时，应覆盖八位来源日期、ISO 日期、仅年份、闰日、非法日期与发行/上传日期不同等自主样本，不依赖参考软件的原文件。

### R4：技术属性保持真实

- 当嵌入文字标签时，系统不得为此重新编码音视频；用户另行请求的转换不受影响。
- 当处理结束时，时长、尺寸、帧率、码率、采样率和声道应取自最终媒体流，不能抄网页数据覆盖。
- 当仅做标签写入时，验收应比较主音视频包/解码内容和时间轴，而不是要求整个文件 SHA256 不变。

### R5：按容器明确兼容能力

- 当容器支持字段时，系统应使用该容器有效的标签表示，独立回读确认。
- 当 Windows 属性处理器不显示某字段而容器回读成功时，系统应区分“已写入”和“Windows 不显示”，不报成下载失败。
- 当字段或容器不支持时，系统应明确说明，不静默换格式、不全局启用未经验证的 mdta 布局。
- 当存在同义标签别名时，验证器应规范化后比较，不能仅按某个固定 ffprobe 键判断丢失。

### R6：组合后处理不丢信息

- 当封面、字幕、VR 或多音轨处理继续改写文件时，最终产物应保留已确认元数据和所有必要流、图片、章节及空间属性。
- 当 SponsorBlock 或区间截取改变时间轴时，章节应对应最终时间轴，不超出成品时长。
- 当同时交付保留的视频和提取音频时，系统应分别按各自内容角色写入并验证，不只处理一个猜测出来的主文件。

### R7：事务与恢复安全

- 当自有 writer 写入时，应使用 StagingArea 的候选与原子采纳 API，不直接改写最终下载目录文件。
- 当字段写入或回读失败但原媒体安全有效时，系统应保留原媒体，记录缺失字段并显示元数据不完整。
- 当候选出现媒体结构损坏、路径不安全或用户取消时，应停止采纳，遵守既有提交边界。
- 当重试或崩溃恢复发生时，应按 attempt 区分控制文件，不能读到上次或另一视频的标签。

### R8：结果与隐私

- 当报告“嵌入成功”时，应具有成品回读证据；工具返回 0 或 PP 完成消息不能独立证明字段正确。
- 当用户没有要求字段、字段没有来源或格式明确不支持时，系统不得把它混入虚假的成功缺失统计。
- 当记录日志时，只记录必要字段名、来源类别、结果码和脱敏摘要；不记录 Cookie、认证信息、完整隐私简介或签名媒体 URL。
- 当用户选择保存元数据文件时，系统才交付精简白名单 sidecar；默认不附加完整 info.json 到成品或输出目录。
- 当 UI 展示选项时，应区分“嵌入元数据”“嵌入封面”“保存元数据文件”；正式扩展 UI 后验证中英与明暗主题。

## 验证矩阵

| 验证层 | 样本 / 场景 | 通过证据 |
| --- | --- | --- |
| 规则 | 日期、角色冲突、空字段、Unicode、多值、非法数值 | 有意义的标准化单测，含来源与拒绝原因 |
| 意图 / CLI | 全局开关 × 任务开关 × 音频预设；快速/单项/批量 | 最终 argv 与任务快照一致，不仅检查 UI 控件 |
| 离线容器 | MP4、M4A、MP3、FLAC、Opus、MKV | 合成样本写入、ffprobe + 必要时原生标签读取，记录工具版本 |
| Windows | 核心属性：标题、年份、艺术家、备注、标记 | 命名 System.* 属性读回及实际属性页抽验；记录 OS / handler 环境 |
| 保真 | 原生标签、音视频、字幕、封面、章节、VR 空间数据 | 修改前后结构和媒体内容对照；流丢失直接失败 |
| 回退 | 工具缺失、磁盘不足、写入失败、超时、取消、重试 | 原文件可用、候选不交付、错误落在正确阶段 |
| 真实流程 | 普通视频、确认音乐作品、多作者、列表、X 视频、VR | 完整提取到最终文件回读；失败样本独立归档 |
| 交付 | 最终打包 EXE 与实际工具组合 | 重新进行核心样本验收，不能用开发环境通过代替 |

上表是完整验收目标，各层实际通过范围见实施记录；不能以自动测试代替真实下载、Windows 显示和成品 EXE 媒体操作验收。

## 本轮设计采用的产品默认值

1. 普通视频允许用真实创作者或频道作兼容作者显示，来源角色独立记录；音乐作品优先结构化艺术家。
2. MP4/M4A 的兼容年份字段计划写四位年份，完整上传日和发行日分别保存到命名空间扩展标签；上线前用自主样本验证。
3. 首版保持一个“嵌入元数据”开关，封面独立，提供简洁结果提示；字段预览和手动覆盖留到后续增强。
