# #105 本地修复与实机测试

2026-09-22。本地源码试用版；基于 v3.7.5，版本号保持 3.7.5。尚未打包、提交、推送或发布。

## 已实现

- 新建任务窗口的正文进入 Fluent 滚动区，重新解析／取消／下载按钮固定在正文外；原先遮挡标题栏的空容器改成真实的滚动内容容器。
- 窗口宽高和位置都按当前屏幕可用区域限制，支持非零和负坐标；移除解析完成后的宽度锁。监听屏幕和可用区域变化，在普通窗口状态下重新检查边界，最大化／最小化时保留系统状态。
- 加载页就按任务模式选择默认尺寸；用户已经调整窗口，或后续重新解析时，保留当前几何。裁切只展开内容、自动滚动到选项，不再带动外窗加高。
- 下载选项按可用宽度换行，裁切的时间与模式拆为两行；普通和 VR 的简易／专业页按当前页提供尺寸提示。
- 普通专业模式改用 Fluent 表格，与 VR、外层滚动区共用滚动参数。表格使用逐像素滚动；触控板像素输入直接响应，嵌套滚动到边界后将后续输入交给上一层。
- 音视频流卡片共用 200 ms 的正文高度过渡和箭头旋转；快速反向操作从当前状态继续，隐藏时结束动画并同步状态。收起内容退出焦点交互，保留已有格式选择。
- 普通专业模式的叠放流表采用四行高度预算，整合／单独流表采用六行高度预算，避免原先两行视口及整表无界增高两种行为；VR 两张流表统一高度上限。仍保留 VR 原有单选语义和普通音轨多选语义。
- 播放列表里的“选择格式”独立弹窗同步增加正文滚动和屏幕边界保护。

### 第二轮：隐藏外层滚动条与背景重绘

- 新建任务和播放列表格式弹窗的最外层正文隐藏横纵滚动条；滚轮、触控板以及 Tab 焦点自动滚入可见区仍可用。流表和页面内部的滚动条保留。
- 顶层窗口、格式卡片及滚动视口在绘制控件之前填充当前主题底色，避免展开、收起和缩放新露出的区域依赖透明背景。滚动视口在 QAbstractScrollArea 转发的 paintEvent 中绘制，不替换 Fluent 已安装事件过滤器的视口。
- 手风琴收起过程中保留正常配色，到内容隐藏后才禁用；动画期间拦截鼠标，已选音轨保持不变。
- 普通／VR 流表显式清除原生交替行底色，保留 Fluent 委托的行背景。截图中已确认并修正深色主题出现浅色交替行的问题。
- 同时检查 Light/Dark 动画中间帧的实际背景色，防止用“不是白色”这样的宽松判断漏掉黑色未绘制区域。离屏绘制通过不等于 Windows 原生合成器上的闪烁已经验收。

没有修改下载任务构造、解析调度、缓存或发布版本。菜单仍使用原有 Fluent ComboBox；本轮统一的是流表格滚动、卡片展开及窗口承载方式，没有重写菜单动画。

### 第三轮：点击闪烁、加载切换及默认窗口尺寸

用户实机反馈第二轮后仍会在专业模式手风琴及整个窗口加载时闪烁，故第二轮不能视为闪烁问题验收通过。本轮继续处理可确认的事件与布局问题：

- 标题原本只接管 mouseReleaseEvent，按下事件可传播到 CardWidget，松开却不能清除卡片的按下状态。现在标题完整接管左键按下／松开，并把反馈限制在展开按钮；卡片容器不再随 hover/press 整块变色，正文高度和箭头动画保留。
- 外层透明样式不再向全部 QWidget 子孙强加透明背景；只配置滚动容器和内容容器的自动填充。普通／VR 流表自己的主题样式保留。
- 焦点自动滚入仅响应 Tab、Shift+Tab 和快捷键。鼠标点击不会因为焦点变化再次拉动外层正文。
- 顶层／卡片的 Qt Window 调色板与绘制底色同步；解析结果先构造并显示，再调整可能变化的窗口几何，清理旧结果时先隐藏旧控件，再延迟销毁。
- 普通任务默认 **960×920**，VR **1000×920**，播放列表／频道 **1040×840**，字幕／封面 **840×600**（均为逻辑像素）。加载页直接使用相同模式的默认尺寸，取消原先 600×400 加载小窗到结果页的大幅跳变。小屏仍按 availableGeometry 限制，手动调整后的几何仍保留。
- 桌面默认专业模式下，两张音视频卡片的标题、输出格式、下载目录和底部操作需同时可见。叠放流表保留四行高度预算，为音频标题让出空间；当前本机可用区对应的截图和几何断言已通过。音频展开后仍允许内部滚动。
- 本机 Qt 当前读取到可用区 **1707×1019、devicePixelRatio=1.5**。按该可用区补充桌面尺寸的明暗截图，位于 `build/issue-105-click/desktop-*.png`。这些仍是离屏合成内容，未把运行中的用户窗口或真实视频解析当作验收证据；此前的 640×480 截图属于极端小屏验证，不是默认布局。

本轮已覆盖真实鼠标按下／松开后的卡片状态、明暗背景一致性、鼠标焦点不拉动页面、键盘焦点仍能滚入、加载到结果页保持默认尺寸，以及旧控件在延迟销毁前退出显示。抓图会主动重绘，因此静态图和 grab() 中间帧不能证明 Windows 原生合成器没有闪帧；需用户再次验证两个实机触发点。

## 实机启动

先退出已有 FluentYTDL 实例（包括托盘中的实例），再在 PowerShell 运行当前源码：

```powershell
Set-Location 'D:\ALL Projects\YouTube\FluentYTDL'
& '.\.venv\Scripts\python.exe' '.\main.py'
```

不要使用旧安装包或以前生成的 EXE 判断这次修复；这些文件尚未重新构建。源码启动会正常使用本项目的数据／账户配置，并非离屏合成数据演示。

优先按原先能触发问题的分辨率和缩放组合测试：

1. 粘贴原视频链接，确认“下载／取消”始终可见；滚动到下载目录，展开裁切，再切简易／专业模式。
2. 从标题栏左上角、中部拖动；缩小窗口、最大化再还原；在不同缩放的屏幕之间拖动后重新解析，确认不会跳回旧位置或被撑大。
3. 专业模式分别滚动视频、音频列表和外层正文；滚到底继续滚，应能进入外层。外层滚动条应不可见，内部流表滚动条仍可拖动；用 Tab 移到下载目录时应自动滚入视口。
4. 快速展开／收起两张流卡片，尤其在动画尚未结束时反向点击；多选音轨后操作，确认选中数量和格式不丢失。
5. 打开播放列表里的格式选择弹窗，以及 VR 专业模式，确认同样可滚动、可操作；检查下载模式和输出格式菜单是否还存在用户反馈的突兀动画。
6. 在明／暗主题下连续缩放窗口、最大化还原、快速开合音视频流卡片及裁切区域，观察正文空白处、卡片底部和表格交替行，确认没有白色闪帧或黑色缺块。

反馈时附上：分辨率、Windows 缩放、窗口模式／页面、使用滚轮还是触控板，以及出问题时的截图或短录屏。若同一界面只有一处卡顿，记录准确的控件和鼠标落点，便于区分内层表格、外层正文与下拉菜单。

## 剩余边界

- 真实高 DPI、屏幕旋转／移除、最大化还原和原生拖动手感待用户验收；尚无动画帧率或性能提升承诺。
- 640×480 以下的逻辑可用区不在当前完整验收范围；异常长内容保留横向滚动能力，但第二轮已隐藏外层可见滚动条。
- 本轮覆盖新建任务及其格式选择窗口。主窗口、日志／消息等其他独立窗口和其余遮罩对话框尚未统一改造，原研究中的邻近窗口风险继续保留。
- 回滚可回退本轮 UI 代码和翻译位置更新；没有数据迁移、配置清空或版本升级操作。
