# 需求与验收标准

## 目标与用户场景

用户需要知道下载成品实际包含哪些信息，而不是依赖 Windows 属性页有限的栏目。主要场景：核对作者/日期，确认视频帧率与分辨率，查看多音轨及字幕，辨别字段缺失和读取限制，导出可用于排查的结果。

首版采用一个本地文件、一个活动读取作业；音视频同页，所有操作只读媒体文件。

## R1 导航与输入

- 当主窗口显示侧边栏时，应在“任务”之后提供“媒体信息”入口；设置保留底部位置，下载徽标逻辑不变。
- 当用户选择或拖入一个可读取的本地普通文件时，应开始识别，显示文件名和状态。
- 当拖入多个文件、文件夹、网络 URL 或播放列表时，应明确提示首版支持单个本地媒体文件，不静默挑选一个或递归扫描。
- 当用户导入后切换其他页面再返回时，应保留本次结果；不持久化最近文件列表。

## R2 文件与技术信息

- 当基础探测成功时，应展示容器、文件大小、时长，以及每条视频、音频、字幕、附件流，保留原 stream index。
- 当存在多个视频或音频流时，应分别展示；概览可选取默认流，但必须允许切换。
- 当只有封面图像而没有视频正文流时，应按音频文件展示，不能把封面尺寸当视频分辨率。
- 应区分平均帧率、参考帧率、文件报告的总帧数；不通过“帧率×时长”伪造帧数。
- 应区分容器总码率、单条视频码率与单条音轨码率；任何计算值必须显示来源和公式说明。
- 对无效分数、`N/A`、非有限值和无效时长，应显示不可用及原因，不能显示误导性的 0。

## R3 标签及来源

- 当文件存在可读取标签时，应展示标题、作者/艺术家、日期/年份、简介、备注/来源、分类/关键词、版权，以及存在的专辑/曲目/剧集字段。
- 每个字段应能够查看读取器、原生键及作用域；同一键的多个值不按逗号随意拆分或只保留第一个。
- 若文件没有明确作者角色，应显示“作者/艺术家”，角色为“未标注”；不由名字猜测频道或音乐作者。FluentYTDL 角色字段应注明“文件声明”。
- 当文件标签与其他作用域或读取器报告冲突时，应保留候选值和差异说明，不静默覆盖。
- 没有读取到字段时，应区分“未提供”“此格式暂不读取”“读取失败”“已截断”；不得自动归因于漏写。

## R4 页面与可访问性（2026-09-21 用户修订）

- 应以内容、视频、音频、文件、来源、简介、章节等类型卡片呈现；删除字段表格和页签。缺失数据不建立占位行/空卡片；读取详情保留在“更多”中。
- 保留截图要求的类型、大小、位置、修改日期、标题、时长、宽高、备注、作者、年份、帧率、视频/总码率，展示已有的额外编码/位深/色彩/音轨等数据。关键数值可选中或按卡片复制，长文本按需展开，不撑破布局。
- 应沿用 Fluent 控件、应用主题和字体，支持浅色/深色与中英文。
- 当 DPI 为 100%、150%、200% 或侧边栏展开/收起时，操作按钮和字段名称仍可访问；窄宽度采用纵向排列，不强迫固定宽度。
- UI 显示“正在读取/正在补充标签”等真实阶段，不用计时器虚构百分比。

## R5 作业、取消与退出

- 当进行任何文件读取、外部进程或原生标签解析时，主窗口应仍可操作，不能在 Qt 主线程执行阻塞工作。
- 当用户取消或更换文件时，应取消旧作业，只接受当前 request_id 的结果；取消后的旧结果不得覆盖新文件。
- 应限制为一个活动作业和至多一个待开始选择；连续拖放以最后一次有效选择为准。
- 关闭到托盘与切换页面不等于取消；真正退出/重启时应停止本页拥有的子进程和线程，不影响别的工具进程。
- 当文件在读取期间大小、修改时间或可用文件身份变化时，应提示“文件读取期间发生变化，请重新识别”，不能标为一致快照。

## R6 部分结果与异常

- 原生标签补充失败而基础技术探测成功时，应保留技术结果并提示标签读取未完成。
- FFprobe 不存在、文件无权限、空文件、不支持的内容、损坏文件、超时或输出超限，应分别给出可理解的提示与重试/组件设置入口。
- 只读的本地磁盘、中文/空格/emoji 路径及纯视频、纯音频应作为首版验收案例。
- 读取不应触发下载、标签保存、转码、完整解码或媒体文件的写入；磁盘慢或介质失联应受作业超时约束。

## R7 报告

- 复制摘要使用清洗后的可读卡片内容（默认省略完整路径）；导出 JSON 必须保留原始数值、来源、缺失状态、版本及读取时间，不受显示层清洗影响。
- 导出应由用户选择目的地；默认只含文件名，不含绝对路径，可显式勾选包含路径。
- 报告不自动包含封面二进制、Cookie、下载参数、网页缓存或应用数据库内容；描述/备注等仍是文件标签，导出只由用户主动触发；页面不常驻报告说明，路径与原始结果选项移至导出对话框。
- 默认摘要不包含未知原始标签；导出可选择“包含原始读取结果”，保留截断/省略标记。显示与导出均不自动访问标签中的链接。
- 不得导出覆盖正在检查的媒体文件；相同路径、路径别名及可识别的硬链接身份都必须拦截。

## R8 已完成任务右键直达

- 当右键作用域为单个已完成任务时，应提供“查看媒体信息 / View media info”；点击后自动导航到媒体信息页、载入记录的主成品并开始读取，不要求用户重复选择文件。
- 此入口适用于“全部”“已完成”及其他筛选中的完成行，也适用于应用重启后没有 worker 的历史行；不能只连接实时下载 worker。
- 应沿用任务列表既有右键作用域与勾选规则；多任务作用域或未完成任务禁用该操作，不偷偷选择第一条、不改变已有勾选。
- 菜单打开后若行发生插入、排序、删除或任务重新开始，点击时应重新校验稳定任务身份、单行作用域和完成状态，不打开错行或临时文件。
- 路径来自任务行的有效成品路径；文件存在性、权限与媒体类型在后台重新检查，不能仅依赖可能过期的 `file_exists` 缓存。
- 缺少记录路径、文件已移动/删除、无访问权限或成品为图片/字幕时，应显示具体原因。路径缺失或文件丢失可手动选择媒体，但不自动修订任务记录、不扫描目录、不触发下载。
- 任务交付多个成品时，首版查看任务记录的主成品并明确标注；不承诺恢复历史记录未保存的完整产物列表，其他文件可通过“选择文件”查看。
- 从媒体信息页返回任务列表时，应保留原筛选、勾选、分页数据及滚动位置；连续点击不同任务采用 R5 的取消和最新请求规则。

## 首版外及后续

不包含写入/编辑元数据、批量目录扫描、两文件差异比较、视频播放、自动联网补全、Windows Shell 一致性模拟。完整帧计数、VFR/CFR 判定及逐轨码率全文件统计放入独立后续工作；首版不显示不可用的“深度识别”按钮。

新功能实施须覆盖上述需求并取得运行证据后，再决定发布版本；本设计不预定 3.7.5。
