## 构建与发布交接

完整准备构建使用 `scripts/build.py --target all`，在独立 `build/runs/<id>/` 中重新取得 latest 组件快照，生成 Full、app-core、Setup、更新清单及 SHA256SUMS。构建时保持源码和 Git HEAD 稳定。最终状态、提交、组件身份、输出路径和哈希以本次成功的 `build/latest-result.json` 及其对应 run 报告为准；失败不会覆盖旧成功指针，读取时必须核对版本与提交。

本机 Codex Poppler 的 ICU DLL 曾污染 Qt 构建发现，只在构建子进程 PATH 中过滤 `codex-runtimes`，不修改系统 PATH。构建后用当次组件目录复跑真实元数据测试，避免开发机旧组件代替最终组合。

准备阶段不创建公共 tag。公开发布仍须 PR 门禁通过并合入 main，随后由对应 `v3.7.4` tag 触发发布流水线。该流水线重新获取最新组件、执行隔离 Windows runner 安装/覆盖/卸载验收、核验 Draft 后发布同一批文件。不得拿本地构建或 `publish=false` Actions Artifact 充当公共 Release。

真实 VR/HDR、完整在线下载与播放器兼容验收边界继续按元数据实施记录保留；本地打包和合成样本不能替代这些结果。发布后另行核对五个公共资产、Latest、GitHub/Cloudflare stable/pre 清单及 app-core 哈希。
